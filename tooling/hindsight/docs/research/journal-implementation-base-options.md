# Decision brief: journal implementation base and historical-source integration

**Proposal for Ivan’s decision, not a selection:** start implementation from `47510ddba6627cd1e8e5b31c55feacc816d8f17a`, then incorporate `7b165b3ee97e7e4bbddcb8eafe089f7f1237e0ab` as an immutable, non-importable source capsule and implement the production historical reader as a separate successor-owned, read-only tool. Pin that tool’s actual artifact and contracts in `HistoricalReaderExecutionBinding/v1`; do not equate the capsule, a port, or the source revision with the runnable execution identity. This keeps every settled journal and PostgreSQL boundary while avoiding a broad sibling-history merge.

## Source shape and contracts that stay frozen

The accepted model has four distinct objects:

1. **Historical artifact bytes:** inventory hashes the exact opened bytes before parsing; locator is diagnostic, not identity ([inventory contract](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-compatibility-design.md#L116-L145)).
2. **Historical source capsule:** provenance evidence containing unchanged source bytes. It is not itself a reader output, tool, or execution identity.
3. **Historical reader implementation:** the immutable `READER` tool that implements one or more exact members and emits only registered nonauthorizing success/failure bodies.
4. **Execution binding:** the one-member-to-tool identity. Its implementation, input, invocation, and output contracts must equal the bound tool; its source revision, wire contract, and reader contract ID must equal the selected registry member ([binding rules](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-acceptance-evidence.md#L2140-L2165)).

Keep `7b165b3…`, every complete selector, derived contract ID, registry order/digests, dependency role, and wire identifier unchanged. Preserve the default canonical-JSON-plus-one-LF contract, the progress compact-ASCII/no-LF raw contract, and the encrypted-preimage canonical/no-LF contract as three different representations ([wire contracts](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-compatibility-design.md#L201-L208), [special cases](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-compatibility-design.md#L272-L286)). Reader outputs retain `authority=NONE` and cannot prove or enter `J/P/R/M/V` ([output boundary](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-compatibility-design.md#L573-L612)). A grammar-changing fix requires a new reader-contract identity; it cannot silently replace a reader already bound by a manifest ([change rule](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-compatibility-design.md#L108-L114)).

## Verification prerequisites and evidence limits

Git/text inspection at revision `47510ddba6627cd1e8e5b31c55feacc816d8f17a` verified the ancestry and merge bases, unchanged accepted-design blobs, changed-path inventories, exact three-file hashes and import closure, absence of historical modules at that revision, and separation between validators, path-coupled readers, writers, mutation callbacks, and tests. No module was imported, no test or prototype ran, and no runtime, database, provider, retained artifact, or target-release source was inspected.

Before implementation can claim the reader binding:

- verify every copied capsule byte, blob, length, SHA-256, origin path, and dependency entry during build; prove the release contains the verified implementation and needs no runtime Git access;
- bind each registry member one-to-one to the immutable tool and its exact input/invocation/output contracts, and reject one-field changes to the member, tool, implementation, wire, contract ID, or source revision;
- run the accepted finite corpus and three-way differential checks across the immutable reader tool, successor discovery/projection, and an independent oracle, covering exact bytes, LF distinctions, every registered version/variant, dependency failures/cycles, raw identities, dispositions, `authority=NONE`, and no fallback ([required differential](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-acceptance-evidence.md#L7298-L7349)); and
- prove historical reader outputs cannot reach successor stage mutation interfaces. If alternative B is chosen, separately prove the legacy writer/mutator surface is unreachable and that path-coupled reads consume only the already acquired stable dependency bytes.

Still gated elsewhere are transaction/recovery orchestration, mutation/compatibility integration, implementation sequencing, target-release source/interface verification, PostgreSQL implementation qualification, release/support-profile qualification, deployment admission, and live authority. The accepted schema explicitly leaves issues 107–111 separate ([remaining boundaries](https://github.com/nisavid/agents/blob/47510ddba6627cd1e8e5b31c55feacc816d8f17a/tooling/hindsight/docs/research/journal-postgresql-schema-interfaces.md#L2955-L2960)); design acceptance alone is not an implementation, release, or deployment result ([evidence gates](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-acceptance-evidence.md#L7873-L7923)).
