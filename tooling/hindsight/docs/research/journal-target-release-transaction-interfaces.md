# Target-release journal transaction-interface verification

**Disposition: no, with bounded source concerns.** At Hindsight release 0.8.4, the inspected target APIs expose useful low-level PostgreSQL pieces: pooled connection acquisition, generic execute/fetch methods, context-managed transactions, and transactional worker claims. They do not themselves expose or route the complete accepted trusted-adapter contract: stage-specific capability surfaces, adapter-owned durability and isolation controls, an acknowledged-versus-ambiguous commit result, exact stage ambiguity resolution, activation-bound session continuity with a nonpersistent witness, or monotonic fencing of every writer path. Those remain successor additions or integration work. This is a source-shape result, not a claim that the protocol runs.

## Accepted boundary used for comparison

The accepted design keeps J, P, R, M, and V in the target PostgreSQL database and requires the trusted adapter to own each stage from BEGIN through acknowledged COMMIT, set and immediately verify synchronous_commit=on, and withhold success until acknowledgement ([publication decision](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-publication-design.md#L20-L43)). M additionally runs at serializable isolation and atomically combines the target compare-and-swap, mutation receipt, generation, and lineage advance; a lost acknowledgement is resolved from the exact receipt, generation, and postimage ([M contract](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-publication-design.md#L819-L903)).

Recovery must distinguish committed, conclusively aborted, and still ambiguous attempts. It exact-reads each stage, never remutates on an uncertain M, and returns STAGE_AMBIGUOUS when the bounded resolution wait expires ([ambiguity contract](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-restart-design.md#L655-L707)). Activation and every M use one dedicated backend session with a session-local capability witness; adapter restart, connection replacement, server restart, or uncertainty fences the old epoch ([continuity contract](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-restart-design.md#L709-L764), [access boundary](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-publication-design.md#L1330-L1364)). The accepted schema exposes narrow C-role adapters, treats a protected-function return as provisional, and assigns connection acquisition, transaction setup, one entrypoint, durability verification, COMMIT, acknowledgement, and exact lost-acknowledgement readback to the adapter ([adapter boundary](https://github.com/nisavid/agents/blob/47510ddba6627cd1e8e5b31c55feacc816d8f17a/tooling/hindsight/docs/research/journal-postgresql-schema-interfaces.md#L2283-L2306)). These requirements, not generic PostgreSQL possibility, are the comparison bar.

## Missing interfaces and downstream planning implications

For issue [107](https://github.com/nisavid/agents/issues/107), the implementation plan needs a transaction-owning adapter surface that fixes: dedicated primary-session acquisition and retention; stage-specific transaction modes; setting and immediately verifying synchronous_commit; serializable M; one protected entrypoint per transaction; transaction identity capture; commit acknowledgement classification; exact readback after a commit-path exception; bounded ambiguity resolution; and invalidation of the old epoch on session loss. The current context manager may be wrapped or extended, but treating its normal return as the whole protocol would omit the accepted provisional/ambiguous distinction.

For issue [108](https://github.com/nisavid/agents/issues/108), current MemoryEngine and WorkerPoller routes cannot be reused as journal authority merely because they use PostgreSQL transactions. Claim commits before task execution, task execution occurs later, and completion/failure is written separately ([execution path](https://github.com/vectorize-io/hindsight/blob/92f433c90409636804c0797071a4abbe141f76c5/hindsight-api-slim/hindsight_api/worker/poller.py#L663-L763)). The plan must identify every target writer, route the selected M mutation through the adapter-owned connection, deny protected mutation functions to ordinary API/worker pools, and keep cache invalidation, webhooks, maintenance, and other post-commit work outside the authoritative M result. Compatibility integration must use the already accepted distinct fence, admission, continuity, publication, mutation, and verification capabilities; local task cancellation and graceful shutdown are not substitutes ([accepted capability split](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-compatibility-design.md#L3548-L3599)). Historical-reader outputs remain nonauthorizing and do not enter these transaction interfaces.

For issue [109](https://github.com/nisavid/agents/issues/109), evidence should advance in dependency order without claiming runtime success from source availability: close source dependencies; implement typed adapter outcomes and the protected call surface; qualify logical SQL, role denial, lock order, and serializable races; inject failures before commit and after server commit but before client acknowledgement; prove exact readback and no duplicate M; then qualify session replacement, adapter/server restart, pool behavior, physical durability, and the exact release artifact. The real-PostgreSQL suite must record effective synchronous_commit, fsync, full_page_writes, wal_sync_method, isolation, schema and grants, as already required by the accepted evidence contract ([qualification requirements](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-acceptance-evidence.md#L7501-L7523)). Wheel, source-distribution, and installed-runtime equality to commit 92f433c9 remain separate release gates.
