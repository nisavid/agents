# Target-release journal transaction-interface verification

**Disposition: no; the bounded source packet is sufficient for that conclusion.** Hindsight 0.8.4 exposes pooled connection acquisition, generic SQL methods, wrapper-level transaction contexts, transaction-local retain helpers, and transactional worker claims. The inspected release does not expose or route the complete accepted trusted-adapter contract: stage-specific transaction controls, immediate durability verification, acknowledged-versus-ambiguous commit outcomes, exact stage-resolution methods, activation-bound session continuity with a nonpersistent witness, or monotonic fencing across every writer path. Those capabilities remain successor additions or integration work. This report establishes source shape, not runtime behavior.

## Accepted boundary used for comparison

The accepted design keeps `J`, `P`, `R`, `M`, and `V` in the target PostgreSQL database. A trusted adapter owns each stage from connection acquisition and `BEGIN` through the single protected call, an immediate effective `synchronous_commit=on` check, `COMMIT`, and acknowledgement; callers receive neither the connection nor an opportunity to insert SQL ([transaction boundary](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-publication-design.md#L20-L43), [adapter boundary](https://github.com/nisavid/agents/blob/47510ddba6627cd1e8e5b31c55feacc816d8f17a/tooling/hindsight/docs/research/journal-postgresql-schema-interfaces.md#L2283-L2306)). `M` must run at serializable isolation and atomically combine the target compare-and-swap, receipt, target generation, and lineage advance. Lost acknowledgement is resolved from the exact receipt, generation, and postimage without remutation ([mutation contract](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-publication-design.md#L819-L903)).

Recovery distinguishes committed, conclusively aborted, and still ambiguous attempts; a bounded unresolved `M` returns `STAGE_AMBIGUOUS(M)` and never retries or verifies ([ambiguity contract](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-restart-design.md#L655-L707)). Activation and every `M` share one dedicated backend session and session-local capability witness. Connection replacement, adapter or server restart, or continuity uncertainty fences the old epoch ([continuity contract](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-restart-design.md#L709-L764)). The accepted `FW03` protected function, not the client, derives the server transaction identity ([work interface](https://github.com/nisavid/agents/blob/47510ddba6627cd1e8e5b31c55feacc816d8f17a/tooling/hindsight/docs/research/journal-postgresql-schema-interfaces.md#L2218-L2225)).

## Downstream planning implications

[Define journal transaction and recovery boundaries](https://github.com/nisavid/agents/issues/107) should specify one adapter-owned stage runner and one dedicated continuity-session lifecycle. The plan must evaluate the typed wrapper scope, generic SQL passthrough, and a separately pinned raw-driver interface rather than assume any one is the complete contract. It must place the ambiguity boundary around commit acknowledgement, exact-read through the authoritative primary, and fence on session loss. It should not add a client-supplied transaction identity or require a wrapper identity accessor; PostgreSQL derives the accepted `FW03` identity.

[Define journal mutation and compatibility integration](https://github.com/nisavid/agents/issues/108) cannot treat the current retain orchestrator as the atomic mutation merely because its mini-batches use transactions or because one conditional callback shares a connection. The plan must identify the exact target rows and every writer, route the selected compare-and-swap through the activation-bound connection, and commit the target change with the protected `M` receipt, generation, and lineage. It must also place outbox, ANN, metadata, hooks, cache work, and maintenance on explicit sides of that boundary. The current low-level connection parameters are possible extraction seams, not evidence that this integration already exists. Historical-reader results remain `authority=NONE` and cannot enter `J/P/R/M/V` ([accepted reader boundary](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-compatibility-design.md#L573-L612)).

[Set journal implementation sequencing and evidence gates](https://github.com/nisavid/agents/issues/109) may now treat the two explicit source-owner gaps as closed for this bounded investigation. It should still order evidence by dependency: implement typed adapter outcomes and protected calls; qualify role denial, lock order, isolation, and race behavior; inject failures before commit and after server commit but before client acknowledgement; prove exact readback and no duplicate `M`; then qualify session replacement, adapter/server restart, pool behavior, physical durability, and the exact release artifact. Source availability alone is not a runtime result.

## Future verification and remaining unknowns

Implementation qualification must use an actual PostgreSQL server and record the server/build, effective `synchronous_commit`, `fsync`, `full_page_writes`, `wal_sync_method`, schema and migration digests, grants, isolation, and topology ([qualification contract](https://github.com/nisavid/agents/blob/90108b516f5a1c460980a93670348f6e228124f2/tooling/hindsight/docs/journal-acceptance-evidence.md#L7501-L7523)). If the implementation uses asyncpg below the wrapper, its exact version and artifact must be pinned and its explicit transaction, cancellation, pool reset/release, replacement, and commit-exception behavior verified. Wheel, source-distribution, and installed-runtime equality to commit `92f433c90409636804c0797071a4abbe141f76c5` remain separate release gates.

The packet does not establish the SQL of every helper called by retain or the behavior of the raw driver. Those facts are not needed for the bounded negative: the inspected wrapper signatures and routed acquisition, mutation, cancellation, and worker boundaries already show that Hindsight 0.8.4 does not expose the complete accepted first-class adapter surface. A later proposal to reuse a specific uninspected helper or raw-driver method needs separately scoped source and runtime evidence.
